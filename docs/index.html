01 / The observer’s remit

Three lenses.
No single health score.

One background model call reviews all enabled lenses. Findings explain observations, confidence, possible causes, suggestions, and source quotes—not a verdict on your agent.

01

Efficiency & friction

Notice repeated work, unproductive loops, or instruction friction that makes progress harder than it needs to be.

02

Confusion

Surface unresolved uncertainty, conflicting assumptions, and signs the agent may be working from a mistaken understanding.

03

Goal alignment

Compare the work with your recorded requests and constraints. The agent’s own plan cannot become your authorization.

Built for the space between turns.

By default, review every 5 successful completed turns (including tool-use turns), with at least 30 seconds between starts. Unassessed tail activity is reviewed after the agent settles, including after an abort; cooldown may delay it.

Only one review runs at a time. Pending requests coalesce to the latest completed checkpoint, not a backlog. Nothing blocks tools, changes working context, or automatically opens alerts.

02 / Start observing

Install. Work normally.
Look when you need to.

No goal-setting ceremony. Continue your conversation; only interactive messages observed while the extension is loaded can establish your intent.

Requires current Pi extension APIs. Tested with Pi 1.5.0. Runtime dependencies come from Pi; no build step is required.

  1. Install the tagged release

    pi install git:github.com/moejay/pi-observer@v1.0.0

  2. Load it in your Pi session

    /reload

    Or start a new session. Loading enables extra model calls with your Pi credentials.

  3. Open your first review

    /assess now
/assess

    The review runs in the background. Reopen /assess after it finishes to see the new snapshot.

03 / From observation to understanding

A report, not a red light.

Findings come first, followed by progress and your goal as understood from your messages. Open details to inspect the quotes behind a judgment.

Reports are on-demand snapshots, not live dialogs. “No concerns observed” does not mean the work is correct.

04 / Your controls

Quiet defaults.
Explicit choices.

/assess settings opens toggles and input controls. Edit values, then choose Save to apply or Cancel to discard. Settings are session-local, restored on the active branch across resume and reload—not global defaults.

Command reference
Command What it does
/assess Open the short report. Press d for evidence and review details.
/assess details Open with source quotes, model information, and coverage details.
/assess now Request a review, even while paused. Bypasses cadence and cooldown, never budget limits.
/assess pause / /assess resume Cancel and pause automatic reviews, or resume. Pausing still records your interactive messages.
/assess settings Edit session-local toggles and inputs; explicitly Save or Cancel.
/assess model Choose an available assessment model using Pi’s existing authentication.
/assess model provider/model-id Set a model directly. Use /assess model current to follow the working model.
/assess messages Read your original recorded messages and preceding assistant context. /assess ledger is an alias.
/assess help Show controls and limitations in Pi.

What you can tune

Reviews & lenses
Enabled by default; efficiency, confusion, and alignment on. An empty lens selection disables model assessments.
Cadence
everyTurns: 5 · minIntervalSeconds: 30
Model & sensitivity
current · balanced. Low asks for strong concerns; high invites tentative ones. These are rubrics, not calibrated probabilities.
Display
status by default; widget adds a small summary, silent hides it. Reports remain available.
Input / output / timeout
maxInputChars: 60000 · maxOutputTokens: 2500 · timeoutSeconds: 60

A spending guardrail, not a guarantee

$2 known-cost budget

The default budgetUsd: 2 gates new calls using cumulative known reported observer cost plus a conservative estimate. This includes abandoned branches.

It is a soft cap, not a provider-enforced hard limit. Missing usage or incomplete pricing can make actual spending higher. Set budgetUsd: 0 to prohibit new calls.

Observer tokens and cost appear in the report, separate from Pi’s native session accounting.

05 / Know the boundary

Read-only is not
data-free.

Loading Pi Observer enables extra model calls. By default, bounded session excerpts go to your current working model’s provider. Selecting another assessment model sends them to that provider instead.

What the model sees

Recorded interactive input, preceding assistant proposals, recent assistant text, serialized tool arguments and results, unverified transcript, and a bounded excerpt of effective agent instructions treated as data.

Branch-wide metrics and bounded prior report context may also be included. Thinking/reasoning blocks and images are not forwarded. Content limits exclude prompt and JSON-wrapper overhead.

Your words establish intent

Only interactive input observed while loaded can establish or change the goal. Older history, RPC input, extension messages, summaries, and assistant plans cannot authorize themselves.

Original messages survive compaction on the active branch. Interpretations require exact matching quotes; whether a quote supports the interpretation remains a model judgment. Incomplete goal context disables alignment findings.

Where caution is needed

V1 has no automatic secret redaction. Prompts, tool arguments, and session excerpts may contain sensitive data. Pause reviews or choose an appropriate local model for sensitive work.

Reports, recorded messages, settings, and usage remain in the existing session file; they are not injected into the working agent’s context. Pausing stops reviews, not local message recording.

Not a security boundary

Pi Observer shares Pi’s process and filesystem permissions. An agent with file or shell access could modify the extension, session, or configuration; other trusted extensions can transform input. There is no OS isolation, cryptographic provenance, or tamper-proof authority.

06 / Open by design

Inspect the observer.

No classifier in v1. Assessments are advisory model judgments, not correctness checks. Failed reviews are not automatically retried for the same checkpoint; use /assess now to retry.

Pause, branch navigation, reload, and shutdown cancel outstanding work. Provider cooperation is needed for prompt cancellation; late responses cannot replace another branch’s report.
